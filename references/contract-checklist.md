# API 文档完整性核对

适用于文档维护源与最终调用方页面。项目契约、载体和模板优先；按真实功能与调用关系检查所需内容。

## 按载体分工

| 载体 | 核对职责 |
| --- | --- |
| 权威契约与机器声明 | 请求响应结构、编码、约束、枚举与示例 |
| 本地业务补充 | 用途、业务语义、跨接口取值、结果处理及项目指定补充 |
| 完整调用方页面 | 按项目流程合成相关来源，核对调用所需信息完整性 |

字段和示例在所属维护源核对，发布页体现相关来源的完整契约；具体载体职责按项目规则。

## 来源与功能

已确认需求与设计定义目标行为，同版本机器契约、真实路由、请求解析、Schema、返回及权限行为定义当前事实。新增接口依据已确认方案编写目标契约，实现和运行验证状态分别记录。

机器契约待提供或存在缺项时，可从对应版本的真实入口、运行时 Schema 与返回证据核实，标明推导来源、版本和待核对部分。记录目标与当前行为的差异，依据已确认需求处理实现校准和契约变更。材料尚待确认的字段标明对请求、响应或验收的影响。

完整页面围绕功能或调用流程组织。相关路由分别说明请求与响应，共享规则集中维护；独立能力按导航需要拆分。维护源、业务补充和发布页面各按项目职责承接信息。

## 请求、响应与模式

- 请求说明方法、路径、媒体类型、参数位置及真实编码；权限、数据范围、状态、副作用和前置条件按实际调用要求表达。
- 字段覆盖调用方需要的集合，区分出现条件、必填条件、类型、可空性、范围和默认值。请求的 required 与值可空独立核对；响应的返回条件针对所属对象存在时判断。
- 嵌套对象和数组元素展开必要字段；动态结构或按整体传递的对象说明开放范围、写入与校验方式，以及后续用途。
- 多种互斥模式明确进入条件、专属字段、接受后忽略或拒绝的已声明字段，以及各自响应。额外字段策略由契约确定。
- HTTP 状态、业务码、失败 data 和字段路径符合真实返回；只解释影响调用方处理的错误和恢复行为。

## 取值与业务语义

核对枚举、缺失、null、空字符串、空对象和空数组的实际语义，区分保持原值、替换、追加和清空。时间格式、时区、数组传输及历史兼容沿项目约定表达。

关联取值说明来源操作、响应路径、选取条件、传递及转换方式。区分内部主键、展示名称、业务标识、外部 ID、临时 ID 和稳定资源引用；保持契约要求的精度与原值。

异步功能区分受理与完成，说明结果查询、等待、失败及重试边界。状态、当前值、历史快照和服务端生成字段按确认语义表达。

## 示例与最小验证

示例使用真实载体，与字段、模式、权限和业务约束一致。提供完整普通请求和成功响应；失败或边界示例按解释价值补充。样例注明演示或实测，覆盖必填与必要嵌套结构。示例数据按项目公开范围和脱敏口径选择，认证凭据采用占位符。

高风险操作写明可复现的环境或前置条件、操作和预期结果；验证方法按项目要求，分别记录实际执行、未执行和未覆盖范围。文档审核可以核对已有证据，真实业务调用依赖对应授权与环境。

完成时确认调用方能选择能力、构造请求、解释成功与失败，并找到后续取值来源。发布页按同版本来源核对，具体格式与载体继续遵循项目规范。
